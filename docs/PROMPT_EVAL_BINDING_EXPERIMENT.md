# L2 事实绑定正反例实验（2026-09-06）

## 结论

**保留为下一轮候选，不替换生产 prompt。** 本轮 20 次生成 + 16 次独立 Judge 请求，校园中的内心扩写/同住及关系稿的未知范围扩大有具体改善信号；没有发现整条重要剧情被删掉。仍有额外行动禁令、未指定听者被补成角色知情和一次姓名拼写错误。盲评也未全数跨轮稳定，因此按停止条件没有继续第二组 16 次请求，更不将候选胜出次数当作无缺陷证明。

412 个离线测试通过，默认 12 例未扩大，生产源码、bundle、配置与版本均不变；没有提交或推送。新增三例与实验工具可继续复用，但不能再称为未见留出集。

## 请求前冻结的方案

此前纯规则候选未达到替换生产 prompt 的条件。本轮只尝试 `l2-binding-examples`：保留完整生产 L2 prompt，增加试织机借用、师徒作业与条件性旁听申请两个局部正反例。示例明确不属于当前剧情证据，不把期望字数、固定标题、JSON 或新输出预算加给模型，也不叠加历史失败候选。该方式参考 [OpenAI 推理模型提示建议](https://developers.openai.com/api/docs/guides/reasoning-best-practices#how-to-prompt-reasoning-models-effectively)：无示例效果不足时可以尝试与任务一致的少量示例，但仍需实际验证，不能据此保证效果。

在任何付费请求前写好三个新案例、来源和 rubric：巡演署名/搭档边界、极地样本/条件许可、城邦亲属/和谈流程，各有 8 条按时间排列的 L1。教学示例没有这三个案例或既有四例的专名和具体事件。生成请求不含 rubric；后续评审才读取。案例是本代理编写并复核的合成剧情，具有角色扮演常见的多线推进、物品状态、关系修复和未决承诺；不是来自私人聊天的复制品或真人专家金标准。经过本轮使用后也不再是未见留出集。

保持当前 `deepseek-v4-flash` 生成连接、temperature 0、纯文本、8,000 Token 硬上限、300,000ms 单次超时；接口按原逻辑关闭 DeepSeek 思考。无自动重试、补抽或切换模型。Key 仅从交互 shell 环境读取，不打印、不写入结果，不修改 shell 配置。生产源码、浏览器产物、模型默认项及版本号不改。

预定调用与停止条件：

1. 新三例各生成 production/candidate 两次，共 **12 次串行生成**。顺序 P1、C1、C2、P2，每次逐条落盘；使用唯一新路径，拒绝覆盖既有实验结果。
2. 直接按所有 required facts、因果与禁止断言复核，不只扫描禁词。若出现关键剧情/条件遗漏或新增的关键无依据事实，则不进入后续付费 Judge，也不改例子后重抽同组。
3. 只有新例筛查未见关键回退，才在四个既有开发案例上各生成候选两次（额外 **8 次**），与已保存且指纹相同的 `relationship-process-production-r1/r2.json` 比较。历史基线时间不同，记录这一限制。
4. 若均有可继续验证的改善信号，再使用现有 `pairwise-calibrated-inline-v2.json` 及独立 GPT Judge 双向、两轮盲评；不重校准、不使用单答数值评分。`passed` 只代表判定稳定，不是候选可发布。

不以单个近义词、概括性标题或字数变化直接宣判；明确改变拥有者、知情人、事件是否完成、条件范围/期限，或漏掉关键因果才算实质问题。仅可能造成误读的连接词另列风险，不与确认扩写混为一谈。候选必须在新旧题材同时保留关键剧情，才考虑生产改动。

## 复现生成

以下命令在已加载本地环境变量的 shell 中执行，不包含连接地址或 Key。每次复现换新的结果前缀，不覆盖历史证据。

