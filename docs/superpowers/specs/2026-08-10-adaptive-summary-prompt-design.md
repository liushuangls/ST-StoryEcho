# 递归分层总结设计

日期：2026-08-10

## 决策

移除单一全局剧情骨架，改用同层递归压缩的总结前沿：

```text
L1(1)…L1(10) + L1(11)
→ L2(1-10) + L1(11)

L2(1-10)…L2(41-50) + L2(51-60)
→ L3(1-50) + L2(51-60)
```

L1 直接来自聊天原文。某层数量超过其保留阈值时，把该层最老的一整组压缩为下一层；始终优先处理最低溢出层，并允许向上级联。

## 配置

- L1 合并组大小：可配置，默认 10；
- L2+ 合并组大小：可配置，默认 5；
- L1 输出上限：可配置，默认 3000 Token；
- L2+ 输出上限：可配置，默认 8000 Token；
- 所有接口请求的硬上限：16000 Token。
- 世界书参考：蓝灯优先，剩余容量再选绿灯；蓝绿灯合计最多 50000 字符，绿灯条数可配置、默认 20 条。

Token 上限只作为接口层安全预算，不写进提示词。模型应根据有效信息量自主决定篇幅。

## 高层提示词原则

高层压缩优先保留长期状态、核心因果、关系转折、重要承诺、不可逆后果、关键资源变化和未决主线。省略不影响后续的过程细节、重复互动、寒暄、移动及已解决插曲。层级越高，压缩越强，但不能切断理解当前局面所需的状态链。

来源总结是事件事实的唯一证据。世界书只帮助理解专名和设定，不能证明事件发生。提示词不强制固定标题或 JSON 结构。

## 数据与提交

- 所有层级共用一个按来源时间排列的前沿数组；
- 父节点保存直接子总结快照和输入哈希，不递归复制完整子树；
- 压缩前后校验原文哈希、子总结修订、完整前沿和聊天所有权；
- 成功后原子替换一组子节点；失败或取消保留原节点；
- 高层重新生成只使用保存的直接子总结；
- 旧版本阶段总结迁移为 L1，旧全局骨架丢弃。

## 角色请求

当前前沿中的所有有效节点按时间顺序合并为一条 StoryEcho system/narrator 消息。每个 `<story_echo_summary>` 块标记层级与来源消息范围。

证据优先级为：当前用户输入、近期原文和 MVU 状态优先；总结之间以时间更近、层级更低且证据更明确者优先。显式新篇章边界可以过滤旧 L1 场景细节，但保留 L2+ 长期连续性。

## 验收

- 第 `G1 + 1` 条 L1 触发最老 `G1` 条合并；
- 第 `G+ + 1` 条任意高层总结触发最老 `G+` 条合并；
- 多层同时溢出时先低后高并正确级联；
- 稳定前沿每层不超过其阈值；
- 压缩失败不影响角色生成，也不丢失源总结；
- 完整重建先原子替换 L1，再逐批建立高层；
- 注入协议不再产生 `<story_echo_skeleton>`。
