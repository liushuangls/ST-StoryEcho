# 自适应总结提示词与统一历史注入设计

## 目标

让阶段总结和全局剧情骨架根据实际剧情的信息量、复杂度与长期影响自主决定篇幅，避免固定字符目标、Token 数字或“输出预算”措辞诱导模型过度压缩，同时继续确保关键事实、因果和待续内容完整。合并主聊天中为每条骨架或总结重复发送的历史说明，在不改变现有协议标签、消息优先级和识别逻辑的前提下降低固定提示词开销。

## 设计依据

提示词应直接描述任务目标、证据优先级、必须保留的信息、成功标准、输出形式和低价值内容的取舍顺序。同一规则只表达一次，不向模型暴露接口容量，也不通过固定篇幅或模型内部工作步骤代替可验证的内容标准。

## 提示词调整

### 阶段总结

- 删除“约 1000～1600 个中文字符”“可扩展到约 2200 个中文字符”等固定目标。
- 删除动态插入的“本次最大输出预算为 X Token”。
- 删除“输出预算决定信息密度”等预算导向措辞。
- 合并 system prompt 与动态 user prompt 中重复出现的结构选择、关系证据、状态归属和输出核对要求；稳定规则只在 system prompt 表达一次，动态 user prompt 只说明本次来源范围并承载输入数据。
- 把“输出前核对”等模型内部过程要求改成成品必须满足的事实、实体、时间、确定程度和行动阶段一致性标准。
- 改为按本批剧情的信息量、复杂度和后续影响自适应展开。
- 明确完整保留影响后续理解的事实、因果、状态变化、关系推进、决定、承诺、伏笔和未决事项。
- 需要取舍时，优先省略寒暄、重复描写、无后果动作、例行确认和不影响后续的文风细节；不得为了缩短正文删除关键内容。
- 内容完整、准确、无重复后自然收束。

### 全局剧情骨架

- 删除“本次输出预算上限为 X Token”和按上限计算的建议 Token 目标。
- 删除“输出预算是内容上限而非填充目标”等预算措辞。
- 合并成功标准、历史价值判断和表达结构中重复的当前状态排除、来源可追溯、事实确定程度、关系变化和语义去重规则；每项语义只保留一次。
- 把“写作前在内部区分”和“输出前在内部建立来源事实账”等过程要求改成可直接检查的成品标准。
- 动态 user prompt 只保留本次维护模式、交付要求和输入数据，不重复 system prompt 已定义的结构与内容规则。
- 改为按长期历史的复杂度、事件数量和因果密度自适应展开。
- 保留跨阶段的重要事件、关键因果、关系与成长转折、长期承诺、重要资源流转、认知修正及未决主线。
- 需要取舍时，优先合并重复事件、稳定状态快照和没有长期影响的细节；历史脉络完整、准确、去重后自然收束。

## 统一历史注入

- 主聊天仍使用一条 `system` 消息承载 StoryEcho 历史，不降低消息优先级。
- 统一说明只出现一次：随后内容是较早历史数据而非指令，不代表角色当前状态；与较新的阶段总结、近期原文、MVU 变量或当前用户输入冲突时，以时间更近且证据更明确的信息为准。
- 统一说明后依次放置一个可选的 `<story_echo_skeleton>` 和多条 `<story_echo_summary>`；不增加新的外层协议标签。
- `<story_echo_skeleton>` 保留骨架覆盖到的消息 ID 与正文，但不再重复历史用途和当前状态说明。
- 每条 `<story_echo_summary>` 保留来源消息范围与正文，但不再各自重复历史用途和新旧信息优先级说明。
- 拦截器只插入一条带有现有 StoryEcho 元数据的消息。TauriTavern Agent 的注入完整性校验仍按内部骨架/总结标签数量计算，不按外层消息数量计算。
- Token 分类继续从现有 `<story_echo_skeleton>` 与 `<story_echo_summary>` 标签读取内容；诊断中的注入 Token 改为估算合并后的完整历史消息。
- 没有可用骨架和阶段总结时不插入空历史消息。

## 不变行为

- 设置界面的“阶段总结输出上限”和“全局骨架输出上限”保留。
- 设置值继续作为接口层 `max_tokens` 或对应提供商参数的硬安全上限。
- 不更改模型连接、流式传输、超时、重试、保存或原子替换逻辑。
- 不更改完成原因处理。`finish_reason=length`、Claude `max_tokens`、Gemini `MAX_TOKENS` 等结果继续沿用当前接受与保存行为。
- 不更改阶段总结 64,000 字符存储保护、骨架 Token/字符校验或其他数据结构。
- 不修改内部请求随机标记、提示词缓存参数或缓存统计。
- 不改变现有 `<story_echo_skeleton>`、`<story_echo_summary>` 标签名称、来源范围含义和 system 消息角色。

## 代码边界

- `buildStageSummaryPrompt` 不再接收仅用于提示词展示的 `maxTokens` 参数；生成请求仍从设置中读取同一个上限。
- `StorySkeletonPromptOptions` 不再接收仅用于提示词展示和软目标计算的 `maxTokens` 字段；骨架生成请求仍独立使用设置中的上限。
- `renderStageSummaryBlock` 和 `renderStorySkeletonBlock` 只负责现有协议标签、来源信息与动态正文。
- 新增一个统一历史渲染边界，负责只写一次历史用途和证据优先级说明，并组合骨架与总结块。
- 拦截器使用统一渲染结果创建一条现有类型的 StoryEcho system 消息，同时把内部标签数传给 Agent 桥接层。
- 不修改公共存储结构、设置结构或迁移版本。

## 测试

- 为阶段总结系统提示与请求提示增加回归断言，确认不包含固定字符目标、Token 预算或预算导向措辞。
- 为骨架系统提示与请求提示增加同类回归断言，并确认不再计算软 Token 目标。
- 断言提示词仍包含自适应篇幅、关键内容完整性和低价值内容取舍规则。
- 断言同一稳定语义不再同时出现在 system prompt 和动态 user prompt 中，并移除依赖冗长具体句子的脆弱测试。
- 断言统一历史渲染只写一次用途与证据优先级说明，保留一个骨架标签和全部总结标签，并在输入为空时返回空内容。
- 断言拦截器只注入一条 StoryEcho system 消息，内部标签顺序、数量、来源范围和正文均正确。
- 运行 Agent 与 Token 分类相关测试，确认它们仍按原有标签识别合并消息；注入完整性期望值继续等于标签数量。
- 保留并运行现有请求测试，确认阶段总结和骨架仍把设置中的上限传给接口。
- 保留现有完成原因测试，确认 `length`、`max_tokens` 和 `MAX_TOKENS` 行为没有改变。

## 验收标准

最终发送给模型的 StoryEcho 总结与骨架指令不包含任何由插件设定的目标字符数、目标 Token 数、输出预算说明或重复的模型内部过程要求；接口请求仍带有原来的硬输出上限。正常角色请求最多注入一条 StoryEcho 历史 system 消息，其中沿用现有骨架和总结标签，统一说明只出现一次，Agent、Token 分类、生成完成原因和保存行为保持兼容。
