# StoryEcho 产品规格

## 1. 产品目标

StoryEcho 为 SillyTavern 长篇聊天提供一个可审计、失败安全的上下文压缩层。产品只提供“启用 StoryEcho 上下文管理”一个功能开关。

启用后，请求由以下内容组成：

1. 更早历史形成的全局剧情骨架；
2. 最近若干条阶段总结；
3. 至少配置数量的近期原文；
4. 当前用户输入。

产品不维护独立事实库，不生成或查询向量，不修改当前用户消息，也不把临时注入写回聊天记录。

## 2. 核心参数

- `W`：近期原文窗口，支持完整轮次或消息数；
- `N`：每条阶段总结的目标完整轮数；
- `S`：直接随请求携带的最近阶段总结数量；
- `summary.maxTokens`：阶段总结最大输出；
- `summary.skeletonMaxTokens`：全局骨架最大输出。

## 3. 阶段总结

- 只处理已经完成的“用户 + AI”轮次；
- 普通尾段不足 `N` 轮时不调用 LLM；
- 显式剧情阶段边界可以提前闭合前一批，避免一条总结混合两个独立篇章；
- 单批原文目标上限为 100000 字符，只在完整轮次边界提前结束；
- 单个超长完整轮次保持完整；
- 每条总结保存来源起止消息 ID、来源哈希和更新时间；
- 从第二批起，附带上一条总结末尾最多 5000 字符作衔接；
- 本批原文永远是本批事实与较新变化的最高依据。

## 4. 全局骨架

最近 `S` 条有效总结直接发送，其余为归档总结。

- 第 `S + 1` 条有效总结生成后，首次出现归档总结；
- 首次骨架从当时全部有效总结自旧到新构建；
- 后续每条新总结首次进入归档区时，用旧骨架增量合并；
- 手动完整重建从全部有效总结开始，不继承旧骨架；
- 每个来源批次最多 80000 字符；
- 所有重建批次成功后才原子替换旧骨架；
- 来源失效、超限或总结变化时，骨架标记为 stale，重建前停止注入；
- 人工编辑后的骨架成为后续增量更新基线，不能保存为空。

骨架保留长期事件、关键因果、关系转折、长期目标和未决主线，不承担即时数值面板或角色完整档案。

## 5. 世界书参考

世界书参考可关闭。开启时，每个总结或骨架来源批次可以包含：

- 可用的蓝灯常驻条目，完整条目总计最多 20000 字符；
- 由该批原文直接命中的绿灯条目，默认最多 5 条、完整条目总计最多 10000 字符。

匹配遵守大小写、完整单词、选择性二级键、角色过滤和 `@@dont_activate`。世界书内容中的协议尖括号会被转义。读取失败只记录警告，不阻塞总结。

## 6. 生成前裁剪

生成前必须满足：

- 生成类型是 normal、regenerate 或 swipe；
- 不是 StoryEcho 自身的内部 LLM 请求；
- 当前聊天与排队时聊天一致；
- 被删除的所有非 system 原文已经由有效阶段总结覆盖。

若后台总结落后，保留未覆盖原文并记录延迟裁剪。任何错误都放行原始生成。

注入顺序为：

```text
全局骨架
阶段总结
近期原文
当前用户输入
```

用户显式声明新剧情阶段后，默认省略边界前的最近总结；用户明确询问较早阶段时恢复携带。

## 7. 调度

所有可调用 LLM 或写聊天元数据的任务由同一协调器串行化：

```text
前台生成准备 > 手动处理 > 后台整理
```

前台准备完成后持有租约，直到 AI 回复、生成停止、聊天切换或超时。新前台请求可以取消尚未提交的后台任务。后台每轮只处理一个阶段总结块和一个到期骨架块，避免一次回复触发无界费用。

## 8. 编辑与失效

- 阶段总结支持搜索、分页、编辑和删除；
- 删除最新总结会回退覆盖游标，使原文重新参与请求；
- 删除较旧总结使用覆盖墓碑，不重新发送非常旧的原文；
- 编辑、删楼、Swipe 和分支变化后，从首个不匹配来源范围起截断总结；
- 聊天重命名时迁移所有权；
- 骨架来源不匹配时保留正文供检查，但停止注入。

## 9. 验收标准

1. 关闭总开关时不裁剪、不注入、不调用后台模型。
2. 未总结原文绝不被裁剪。
3. 总结或骨架失败不阻塞正常角色生成。
4. 内部总结请求不被生成拦截器再次排队。
5. 聊天切换或来源变化期间产生的结果不得写入新聊天。
6. 自定义连接失败时按设置回退主连接。
7. 设置页不出现剧情记忆、Embedding、向量或动态召回入口。
8. Token 卡片只展示 StoryEcho 的近期原文与总结/骨架。
