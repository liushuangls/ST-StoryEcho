# StoryEcho 产品规格

## 1. 产品目标

StoryEcho 为 SillyTavern 长篇聊天提供一个可审计、失败安全的上下文压缩层。产品只提供“启用 StoryEcho 上下文管理”一个功能开关。

启用后，请求由以下内容组成：

1. 当前递归分层总结前沿；
2. 至少配置数量的近期原文；
3. 当前用户输入。

产品不维护独立事实库，不生成或查询向量，不修改当前用户消息，也不把临时注入写回聊天记录。

## 2. 核心参数

- `W`：近期原文窗口，支持完整轮次或消息数；
- `N`：每条 L1 总结的目标完整轮数；
- `G1`：L1 合并组大小，默认 10；
- `G+`：L2 及以上同层合并组大小，默认 5；
- `level1MaxTokens`：L1 最大输出，默认 3000；
- `higherLevelMaxTokens`：L2+ 最大输出，默认 8000；
- 接口层统一最大输出为 16000 Token。

## 3. L1 阶段总结

- 只处理已经完成的“用户 + AI”轮次；
- 普通尾段不足 `N` 轮时不调用 LLM；
- 显式剧情阶段边界可以提前闭合前一批，避免一条总结混合两个独立篇章；
- 单批原文目标上限为 100000 字符，只在完整轮次边界提前结束；
- 单个超长完整轮次保持完整；
- 每条总结保存层级、来源起止消息 ID、来源哈希和更新时间；
- 从第二批起，附带上一条总结末尾最多 5000 字符作衔接；
- 本批原文永远是本批事实与较新变化的最高依据。

## 4. 递归高层压缩

L1 数量第一次达到 `G1 + 1` 时，把最老 `G1` 条 L1 压缩为一条 L2，并保留新到达的 L1。此后相同规则重复执行。

L2 及以上层级使用 `G+`：某层达到 `G+ + 1` 条时，把最老 `G+` 条压缩为下一层。若产生的新父节点使更高层溢出，继续向上级联。

高层总结必须：

- 保留长期有效状态、核心因果链、关系与立场转折、重要决定和承诺、不可逆后果、关键资源变化及未决主线；
- 合并重复事实，省略不影响后续的场景过程、寒暄、移动、例行动作和已解决插曲；
- 随层级升高增强压缩，但不能切断理解当前局面所需的状态链；
- 只以直接子总结为事件证据，世界书只能帮助理解设定；
- 根据有效信息量自主决定篇幅，不把接口 Token 上限当作目标。

每个父节点保存直接子总结快照与哈希，以支持来源审计和单条重新生成。生成期间原文、子总结或聊天所有权变化时，结果必须丢弃。

## 5. 世界书参考

世界书参考可关闭。开启时，每个 L1 或高层来源批次可以包含：

- 优先选择可用的蓝灯常驻条目，再用剩余容量选择该批内容直接命中的绿灯条目；
- 蓝灯与绿灯完整条目合计最多 50000 字符；绿灯条数可配置，默认最多 20 条。

匹配遵守大小写、完整单词、选择性二级键、角色过滤和 `@@dont_activate`。世界书内容中的协议尖括号会被转义。读取失败只记录警告，不阻塞总结。

## 6. 生成前裁剪与注入

生成前必须满足：

- 生成类型是 normal、regenerate 或 swipe；
- 不是 StoryEcho 自身的内部 LLM 请求；
- 当前聊天与排队时聊天一致；
- 被删除的所有非 system 原文已经由有效总结覆盖。

若后台总结落后，保留未覆盖原文并记录延迟裁剪。任何错误都放行原始生成。

注入顺序为：

```text
按时间排列的分层总结前沿
近期原文
当前用户输入
```

每个总结块明确标记层级和原文范围。用户显式声明新剧情阶段后，默认省略边界前的 L1 场景细节，但继续携带 L2+ 的长期连续性；用户明确询问较早阶段时恢复携带较早 L1。

## 7. 调度

所有可调用 LLM 或写聊天元数据的任务由同一协调器串行化：

```text
前台生成准备 > 手动处理 > 后台整理
```

前台准备完成后持有租约，直到 AI 回复、生成停止、聊天切换或超时。新前台请求可以取消尚未提交的后台任务。后台每轮最多生成一个 L1 并压缩一个到期组；若仍有层级溢出则继续调度，避免单次回复触发无界费用。

## 8. 编辑、删除与重建

- 所有层级支持搜索、分页、编辑、删除和重新生成；
- 人工编辑保留层级、来源范围和哈希，并显式标记；
- 高层重新生成使用保存的直接子总结快照；
- 删除最新总结会回退覆盖游标，使对应原文重新参与处理；
- 删除较旧总结使用覆盖墓碑，不重新发送非常旧的原文；
- 编辑、删楼、Swipe 和分支变化后，从首个不匹配来源范围起失效；
- 聊天重命名时迁移所有权；
- 完整重建先原子替换全部 L1，再按当前阈值递归建立高层。

## 9. 验收标准

1. 关闭总开关时不裁剪、不注入、不调用后台模型。
2. 未总结原文绝不被裁剪。
3. L1 或高层压缩失败不阻塞正常角色生成。
4. 内部总结请求不被生成拦截器再次排队。
5. 聊天切换、原文变化或总结前沿变化期间产生的结果不得提交。
6. 稳定状态下 L1 条目数不超过 `G1`，每个 L2+ 层不超过 `G+`。
7. 自定义连接失败时按设置回退主连接。
8. 设置页不出现剧情记忆、Embedding、向量或动态召回入口。
9. Token 卡片只展示 StoryEcho 的近期原文与分层总结。
