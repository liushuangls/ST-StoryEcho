# L1 精简证据契约实验

## 冻结方案（真实请求前）

本轮只比较生产 L1 系统提示词与本地候选 `l1-lean-evidence-contract`。候选不修改 `src/`、运行流程、输入正文、世界书、previous summary、输出 Token 上限、生成模型或 Judge；它把生产提示词中重复分散的证据、状态、取舍和表达要求合并为一份较短契约，并只保留一个与评测剧情无关的“要求不等于完成”最小反例。

方法参考 [OpenAI 官方 Prompt Engineering 指南](https://developers.openai.com/api/docs/guides/prompt-engineering) 与 [GPT-5.6 Prompting Best Practices](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6#prompting-best-practices)：每条要求只陈述一次，保留目标、证据、硬约束、输出形态和停止条件，并用代表性评测验证，而不以提示词更短本身判定成功。

### 唯一干预

- 整体替换 L1 system prompt；user prompt、来源消息及所有评测证据不变。
- 保留生产语义：聊天正文优先，旧总结只衔接，世界书不证明事件，实体名称与身份桥接，关键变化和待续事项保留，低价值场景细节省略，中立第三人称输出。
- 把核心保真边界集中为“主体、动作或状态、对象、已明确的发言对象或知情者、条件、确定程度、当前结果”。
- 明确行动阶段与有意义的局部先后；主题归并不得倒置状态链。
- 一个通用反例只示范“要求并答应次日归还”不能写成“已经归还”，不包含任何开发集或留出集实体、题材与预期答案。

### 开发集与请求预算

沿用已冻结的八个 `l1-audit-dev-*` 真实 RP 风格开发用例、3,000 Token 上限、temperature 0、DeepSeek Flash 生成连接和独立 GPT-5.6 Sol Judge。候选运行两轮，每轮 8 次生成与 8 次 Judge，共最多 32 次请求；不自动重试。已有 production 两轮只作同协议参照，不回写。

### 进入留出集的门槛

1. 两轮均无空正文、截断、请求错误或评测协议变化。
2. 恋爱例中“提出公开边界—答应—删除动态”的顺序两轮均正确，且不得再新增“答复由面试结果决定”的来源外条件。
3. 医疗例保持“医生澄清—撤回错误申请—患者选择监测”的顺序，不得错绑澄清者；偶像例不得把归档指示写成已完成。
4. 其余用例不得新增 major/critical 的事实遗漏、主体/对象错绑、错误因果、关系升级、完成阶段升级或世界书覆盖原文。
5. 不能只凭 Judge 总分或正文变短通过。候选输出总字符若比 production 参照增加超过 10%，必须证明重要事实覆盖相应增加；更短也不能补偿事实错误。

若开发集未通过，停止，不查看或运行四个 `l1-audit-holdout-*`，不修改生产 Prompt。若通过，先冻结候选与开发结果哈希，再对 production/candidate 留出集各运行规定轮次；看到留出结果后不再修改同一候选。

## 实测结果

### v1 开发集两轮

`l1-lean-evidence-contract` 两轮共完成 16 次生成与 16 次独立 Judge 请求，无空响应、截断或网络错误。第一轮自动通过 8/8，综合均分 99.5；第二轮通过 7/8，综合均分 98.2。两轮均正确恢复恋爱例的“提出边界—答应—删除动态”，没有新增面试结果决定答复的条件；医疗例两轮因果顺序正确且没有错绑澄清者；偶像例两轮都把评论区归档保持为指示而非完成结果。候选两轮没有 major/critical 幻觉、时序错误或 forbidden claim。

第二轮轨道站例因把“仅作候选，众人未采纳”写成未拆泵状态而没有命中旧硬断言中的“没有拆/未拆/候选方案”字面词，自动判为失败；语义 Judge 将该事实判为 complete，因此这属于机械词表覆盖不足，不回写结果。该稿同时把来源并列给出的样本库升温风险表述成未采纳的明确原因，Judge 记为 minor 幻觉，并保留了营养棒、无人机玩笑和咖啡等低价值过程。世界书例两轮还都把江渝单独用工具柜抵门泛化为“两人”共同动作，均为 minor 主体扩展。

与既有 production 两轮参照相比，v1 自动通过数由 6/8、5/8 提高到 8/8、7/8，关键目标也由逐来源人工复核确认；但 v1 两轮输出总字符分别为 3,625、3,616，production 为 3,186、3,216，平均增加约 13.1%。新增长度主要来自被来源明确标为不改变状态的过程，没有对应的重要事实覆盖收益，超过冻结的 10% 诊断线。因此 v1 不进入留出集。

### 冻结后继候选 v2

v2 保留 v1 全部文字，只替换一条低影响内容省略规则，增加通用决策：来源已经明确某段没有改变决定、状态、关系或目标时，将其当作省略信号，不复述该段，也不机械写“没有改变”；只有省略会造成当前状态歧义时，才保留最短否定。这不改变事实契约、行动阶段示例或输出结构，也不加入开发例答案。

请求前冻结的 v2 为 1,577 Unicode 码点、4,375 UTF-8 字节，相对生产 prompt 仍减少 24.5%；文本 SHA-256 为 `80fbaf870f951a055f8eddb83875a92e9ac79b0623c8939d4e88f7a2995808ff`。来源、Judge 与评测协议继续使用上文已冻结的同一指纹。

v2 先在相同八个开发例运行两轮。除 v1 的事实门槛外，输出总字符须回到不高于两轮 production 平均值 10% 的范围；若仍稳定复述低价值过程、出现任何 major/critical 新错或关键目标回归，则停止，不进入 holdout。

### v2 开发集结果：事实改善稳定，密度门槛未通过

v2 两轮各完成 8 次生成与 8 次独立 Judge 请求，无空响应、截断、网络错误或评测协议变化；两轮自动结果均为 8/8 通过，综合均分分别为 98.7 和 98.9。事实保留均为 100，不确定性与 forbidden claim 安全均为 100。逐来源复核再次确认：恋爱例两轮均保持“提出边界—答应—删除动态”，没有把答复改成取决于面试结果；医疗例两轮均保持“医生澄清—周宁纠误并作废申请—顾禾选择监测”；偶像例两轮均未把归档指示升级为完成。没有 major/critical 幻觉、时序错误或关系/行动阶段升级。

候选仍未达到冻结的密度条件：两轮正文总字符为 3,551 和 3,625，平均 3,588；production 参照平均为 3,201，增长 12.1%，高于 10% 上限。轨道站两轮仍保留营养棒、无人机玩笑等来源已标明不增加状态的过程，第二轮医疗例还保留监测器洗澡问题、跑团争论和买菜。省略规则只把 v1 的平均 3,620.5 字降到 3,588 字，约减少 0.9%，没有形成稳定的高收益压缩改善。

质量方面另有一个稳定 minor 回归：医疗两轮都把 previous summary 中“此前体检发现心律异常”改写成“本次门诊复查中发现”，把发现时间轻微后移。第一轮还有“面试结果”被误列为待续、左手抄字被补写为因右肩不便两处 minor 推断；第二轮没有重现。v1 的世界书例“两人共同抵门”在 v2 两轮未重现。

系统 Prompt 输入缩短仍带来请求开销下降：v2 每轮生成输入共 13,838 Token，production 为 16,022，减少 13.6%；即使候选输出 Token 增长约 11.0%，生成请求的输入加输出总 Token 仍平均减少约 10.6%。但更长的持久化总结会继续进入后续对话，不能只用单次请求 Token 下降抵消密度失败。

### 用户放宽长度门槛后的解封决定

用户随后明确表示生成长度“不用卡太死”。这项产品偏好在任何 holdout 输出被查看前提出，因此从后续实验开始，固定 10% 长度线撤销；长度、输出 Token 和后续注入成本保留为诊断与权衡，不再单独否决语义更可靠的候选。事实反转、主体/对象错绑、知情与授权扩大、行动阶段升级、关键因果倒置和世界书覆盖原文继续作为硬门槛。

为避免直接根据旧短夹具放行，先冻结并运行了三个全新自然长篇 RP 场景、每例 30 条消息，详情见 [L1 自然长篇 RP 验证](PROMPT_EVAL_L1_NATURAL_VALIDATION.md)。v2 在两轮六例中逐来源语义通过 6/6，production 为 4/6；事实保留 98.8 对 92.0，不确定性 100 对 96.5。候选平均正文长 19.5%，但生成请求输入加输出总 Token 仍少约 3.3%，且未出现 major/critical 新错。

据此在不修改 v2 的前提下解封四个 `l1-audit-holdout-*`。Holdout 将对 production 和 v2 各运行两轮；长度只报告，任何关键事实反转、范围扩大、行动阶段升级或 major/critical 新错仍否决候选。看到 holdout 后不再修改同一候选，也不回到开发集补抽。
