# 来源错误定位实验（2026-09-07）

## 结论

**定位环节本身也不稳定，本轮未通过，不进入自动最小修订或生产流程。** 16 次请求全部正常完成，但六次目标错误检查中只报告出三次：表态遗漏两次均定位，新增人物发言四次只定位一次。同一份和谈稿一次报错、一次返回空数组。十次正确对照没有误报，不能用此结果抵消漏查。

相较此前只返回完整修订稿，这次能直接看到报告中的证据和差异说明；但没有报告不等于已经证明没有问题。来源定位与文字修订是不同能力，不能将前轮漏改都归因于编辑执行，也不能说只换成诊断输出就足够。

本轮新增显式本地命令 `eval:localize` 与 30 个离线测试。全量 **56 个测试文件、460 个用例通过**；生产代码、prompt、模型连接与版本均未修改，未 commit/push。

## 请求前冻结

上一轮 GPT 全文核验后，仍有两稿把客观说明写成温策说过的话，一稿漏掉悠承认不舒服的表态。仅看核验后的完整正文，无法区分没有定位到问题与没有落实修订。本轮先独立测**错误定位及其来源证据**，不再生成或修改总结。

按 [OpenAI Docs 的评测设计建议](https://developers.openai.com/api/docs/guides/evaluation-best-practices#example-summarizing-transcripts)，将开放式改写收窄为有具体标准的分类，并加入无错误对照。本轮使用既有 `gpt-5.6-sol` 连接作为受测定位器，不采用文档中的其他模型，不把 GPT 对自身旧稿的检查称为独立质量评审。

### 固定协议与盲化

- 核验 system 为 764 个 Unicode 码点，协议指纹 `5c9601dc19952c6f553fe5fe46128d5ec09fd48ec78c45ee15e0edee0aed61df`。
- 输入集合指纹 `4a23b1ff358dace575fbd0b4dcff7f292a1a74bf0922caa75208e78bbcb59801`（`evalHash(inputs)`，包含本地溯源与标签）。
- 模型只收到通用两类定义、世界背景、按来源顺序编号的正文，以及按原顺序编号的草稿片段；不收到匿名编号、原模型、正反标签、目标锚点、rubric、原生成/核验指令或另一份对照。全文没有被抽成错误片段；草稿分句索引会省略空白行和首尾空白，不删除正文。
- 返回 JSON 文本 `issues`，每项包含类型、来源编号、草稿编号、简短差异说明；不要求输出私有思维过程、质量分或新总结。只在提示词要求 JSON，不新增 API `response_format` 或结构化输出依赖，不改变插件自然语言总结。
- 程序校验 schema、类型、编号范围与重复项，直接从原文还原引用；来源证据必须非空，新增归属必须引用草稿，完全遗漏允许没有草稿引用。最多 16 项问题，每组最多 8 个编号，说明最多 1000 字符。
- `targetEvidenceHit` 只是类型及引用覆盖预设锚点的机械候选匹配。即使类型和编号命中，说明可能判断错误，必须逐条对照语义，不能拿此布尔值当质量通过。`qualityEvaluated=false`，没有自动总分。

## 下一步边界

按请求前标准，这个双类别定位器仍失败，不能拿空 `issues` 自动批准总结，也不增加“检测后再自动改写”的调用链。本轮不为已命中的稿件追加修订请求，不临场修改指令或放宽门槛。

建议暂时停止叠加核验调用，回到**单次生成 prompt 的“保留重要实际表态”最小候选**：这一缺口已有明确来源和可区分的正反例，可以用小规模生成对照检验是否少遗漏，而不是继续重写整套规则。定位器只作为这项检查的辅助，仍需逐来源复核新发言、知情范围及其他副作用；不能因本例两次命中就当作可靠自动评委。

这是新的候选开发方向，不是批准当前定位器或历史修订流程。本轮尚未创建该 prompt、发起生成 A/B 或改变生产；新题材、不同表达方式及真实长链仍未得到验证。
