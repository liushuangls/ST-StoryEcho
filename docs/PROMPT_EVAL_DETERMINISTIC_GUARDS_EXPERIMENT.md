# 阶段总结确定性风险校验实验

## 冻结方案

本轮不再修改生成 Prompt，也不调用生成模型或 Judge。目标是评估一个纯本地、可解释的警告器能否从“原文 + 阶段总结”中识别两类高风险错误：

1. `pending-action-upgraded`：来源只有要求、计划、申请或明确未完成，摘要却把同一事项写成已完成。
2. `explicit-boundary-lost`：来源明确写出未同意、未授权、未执行、未解除或未确认等边界，摘要将其反转为肯定状态，或完全省略对应事项。

按 [OpenAI 官方评测最佳实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)，使用任务特定分类指标、人工标签、典型/边界/对抗样本和隔离留出集，并将自动结果与来源复核结合。准确率容易被大量无问题标签稀释，因此本轮主要报告 precision、recall、F1、FP/FN 和整例完全匹配数。

### 数据与隔离

- 开发集 20 例：可用于调整规则，包含已观察到的归档升级、申请变批准、未执行变已执行、授权边界遗漏，以及“已要求不等于已完成”“来源后续确实完成”“否定同义改写”等反例。
- holdout 10 例：不同实体与物品，覆盖归还、许可、服务器所有权、取消发射、身份和物证所有者；开发门槛通过前不运行结果。
- 全部是本项目既有合成剧情的摘录或同结构扰动，不含真实聊天、Key、URL、rubric 文本或真实模型请求。

### 规则边界

实现仅使用 NFKC/大小写归一化、标点分句、有限状态词表、字符 n-gram 与最长公共子串匹配。它不理解开放域语义，也不能证明两个相似片段指同一事件。为了可审计，输出必须带来源分句、匹配到的摘要分句和固定理由；不自动删除、重写或拒绝保存总结。

开发门槛预先固定为：整体 precision ≥ 0.95、recall ≥ 0.70；两个类别各自 precision ≥ 0.90；总 FP ≤ 1。只有开发通过才运行 holdout；holdout 门槛为整体 precision ≥ 0.90、recall ≥ 0.60、各类 precision ≥ 0.85、总 FP ≤ 1。两者都通过也只表示值得扩大语料，不直接接入生产。

性能基准把 20 个开发例的来源和摘要分别拼接并重复四次，执行 2,000 次；记录单次 p50/p95。目标 p95 < 5ms。该基准只衡量本地字符串算法，不包含消息提取、持久化、网络或模型耗时。

## 开发集校准与冻结

开发阶段保留了每次结果，没有覆盖失败轮：初版因二次复杂度的最长公共子串基准超过一分钟而主动中止；改为预计算字符 n-gram 后，v1 为 14/20、precision 0.692、recall 0.750、p95 5.258ms。随后只针对开发误差处理无对象的开放式未知、保留动作词、逗号内指代和“已要求”作用域；中间 v2–v4 仍未过门槛。最终 v6 达到 20/20，整体及两类 precision/recall 均为 1，基准 p50/p95 为 4.736/4.910ms。

五个错误用例显示的不是同一种可用小修补，而是中文开放表达的结构性问题：

- “馆长要求姜翎归还潮镜”与“姜翎把潮镜归还馆长”因词序变化无法稳定绑定：未归还被写成已归还时漏报；来源后续确实归还时又误报。相同词项并不足以判断是否同一状态更新。
- “长老尚未批准”与“审议通过后才可能开放”使用不同动作词，正确的条件性改写被误报为边界遗漏。
- “不授权转移原服务器所有权”与“原服务器所有权不转移”改变语序后匹配失败，正确摘要被误报。
- “所有者仍未知”没有动作动词，未进入有限风险词表，真实遗漏未被发现。继续扩充名词与同义词只能针对已见表达，不能证明开放剧情中的精度。

性能门槛通过，但质量远低于门槛。**决定：不把确定性校验器接入生产，不作为保存阻断、自动重写或用户告警。** 开发集 20/20 是调参后的拟合结果，隔离 holdout 的 5/10 才揭示泛化不足；不能通过继续根据 holdout 补词后宣称同一留出集通过。

本轮价值是排除了一个看似便宜的方向：没有句法/语义表示时，字符串规则无法可靠区分状态主体、词序、同义动作、后续完成和边界省略。若未来产品新增结构化剧情状态或用户显式声明的守护字段，可复用这种确定性检查；对当前自由文本总结没有足够证据。

下一步回到此前尚未完成的 **L2 命题级发言归属**，但先建立新的开发/holdout 来源和明确人工标签，不复用已经反复调参的七个 L2 场景。该方向已有稳定错误证据（客观旁白被写成人物发言），比继续补 L1 顺序规则更适合下一轮。本轮没有创建 L2 候选。
