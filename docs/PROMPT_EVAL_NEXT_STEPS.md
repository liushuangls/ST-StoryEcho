# A/B、默认 10/5 长链与 L2 去重候选实测

日期：2026-09-06。生产基线为 v0.21.17（`b9f4bd1`）。

## 结论

- 按用户选择继续使用 `deepseek-v4-flash` 生成和评审，继承现有环境变量，不要求额外 Judge Key。这是同模型评估，不属于独立 Judge。
- A/B 对照首轮 12/12 符合预期；另一次两轮重复测试为 22/24 一致且符合预期，包含 1 个无效评审和 1 个位置相关的合格判定变化，稳定性门槛未通过。
- 默认 10/5 长链完成了 61 L1 → 6 L2 → 1 L3 的真实触发过程，四个检查点的固定问答探针全部答对。没有发现本夹具关键事实随层级丢失，但这不是总体质量满分或所有真实聊天的可靠性保证。
- L2 去重候选在 4 个场景的两轮 A/B 中全部判为平局；总字数只下降 3.4%，个别场景反而略长。**不替换生产 L2 提示词**，候选仅保留在本地评测工具中。
- 本轮没有修改 `src/`、浏览器 bundle、用户设置、存储结构、L1/L2+ 的 Token 硬上限，也没有接入 GitHub CI 的真实模型调用。

## A/B 对照校准

采用现有三个开发者合成对照组：物证归属、关系反转、殖民地长期状态。每组包含完整稿与三种坏稿的比较，以及完整稿与自身的平局对照，共 12 对。

| 运行 | 双向比较数 | 一致且符合预期 | 无效评审 | 无法得出一致结论 | 跨轮变化的对照数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首轮冒烟 | 12 | 12 | 0 | 0 | 不适用 |
| 独立的两轮重复 | 24 | 22 | 1 | 2 | 2 |

每个“双向比较”包含两个请求，交换 A/B 的位置，合计 24 + 48 次请求。首轮冒烟不代表稳定性已通过。

两轮测试中的具体问题：

- `relationship-reference-vs-omission` 第 1 轮：交换位置后仍倾向完整稿，但对遗漏稿能否安全用于续写的判断变化，因此判为 `inconclusive`。
- `custody-reference-vs-verbose-error` 第 2 轮：一个方向的响应选出了赢家，却没有列出支持该胜方的差异，被判为无效；这属于评审内容/协议错误，不是 HTTP 或网络失败。

工具要求位置之间的胜方和双方合格标签一致，重复轮次也检查同样的标签。`compare` 模式的 `passed` 仅表示判断一致，不能解释为新候选更好。

本地证据：`evals/results/pairwise-controls-v1.json`、`evals/results/pairwise-controls-repeat.json`（均被 Git 忽略）。

## 默认合并规则长链

夹具：`default-10-5-harbor-delayed-commitments`。61 个批次、366 条消息，原文连接后共 **39,326 个 Unicode 码点**。每批 3 轮是测试批次大小，只有合并阈值 10/5 和输出上限 3000/8000 取自生产默认配置。

| 11 | 最早 10 条 L1 → 第 1 条 L2 |

| 61 | 先产生第 6 条 L2，再把最早 5 条 L2 合并为第 1 条 L3 |

最后活动条目为 L3（消息 0–299）、L2（300–359）、L1（360–365），范围连续且无重叠。共 68 次生成及 4 次问答；68 次生成结束原因均为 `stop`。

| 检查点 | 答对 / 问题数 |
| --- | ---: |
| 全部原文 | 16 / 16 |
| 首次 L2 合并后，仅询问当时可答的事项 | 3 / 3 |

检查内容包括钥匙所有权与保管转交、未复诊伤势、匿名写信者的知情边界、早期只出现一次的镜片归还承诺、旧账纠正、地图备份、化名确认、违约导致合作暂停再试行恢复、表白未决、借物与录音授权条件。

最终问答引用复核可在正文中定位到归还期限、伤势限制、知情边界、账目金额和当前保管人等信息。选择题仍有猜测风险；程序只验证引用片段存在，不能完整验证语义蕴含关系，尤其组合选项的每个子句是否都有足够引用。

最后三个活动条目的正文合计 **4,244** 码点（不含拼接分隔符）。以上是文本体积，不是 Token 数，也不用于推断本地算法性能或模型费用。

局限：只有一个开发者合成长场景，环境气氛与过场采用模板；主要事实没有最后全量复述，但部分状态自然再次提及。测试没有运行前后台队列、窗口裁剪、流式网络、聊天切换及持久化。通过这套探针不能代替真实插件集成测试。

## L2 去重候选实验

旧的小链测试中，校园 L2 曾把押金余额、采访授权条件、感情待答复在正文和末尾待办中重复展开。候选只额外增加“跨段状态去重”规则：主体、条件和状态未变的事实完整写一次；明确更正、反转、条件变化及关键因果仍保留。不设置字数目标，不要求 L2 比单条 L1 短。

对现有四个 L2 场景固定同一生成模型、来源、rubric 和上限，分别生成 production 与 `l2-state-dedup`；每组再做两轮交换位置的 A/B。各候选只生成一次，重复的是 Judge 判断，**尚未测生成本身的随机方差**。

| L2 场景 | 原提示词字数 | 去重候选字数 | 字数变化 | 两轮双向 A/B |
| --- | ---: | ---: | ---: | --- |
| 关系反转 | 459 | 403 | -12.2% | 平局 / 平局 |
| 十条并行剧情 | 364 | 373 | +2.5% | 平局 / 平局 |
| 校园群像 | 920 | 878 | -4.6% | 平局 / 平局 |
| 修仙资源与誓约 | 682 | 689 | +1.0% | 平局 / 平局 |
| 合计 | 2,425 | 2,343 | -3.4% | 无稳定胜出 |

逐项 Judge 对 8 份答案都给出 100 分，但这没有足够区分力。复核还发现：候选校园稿将来源的“留宿细节”扩成“同住、留宿细节”，存在扩义风险；原稿也把“高濑线已经结束”扩成“此后未再出现”。这些不在已列关键判定项里得到扣分，说明不能把当前自动满分当作逐句保真认证。候选在校园和修仙稿中也仍有跨段重复，收益并不充分。

决策：保留 `evals/variants.ts` 作为实验入口，生产提示词不变。下一轮更有价值的是补充这类新增事实/扩义的对照，以及从实际长链输出中建立更长的成对样本；不通过调低阈值或强行限字数制造“优化成功”。

本地证据：`evals/results/l2-production-v1.json`、`l2-dedup-v1.json`、`l2-pairwise-v1.json`（被 Git 忽略）。

## 独立 Judge 复核：GPT-5.6 Sol

完成 1 次连接冒烟、24 次逐项校准和 48 次 A/B 对照请求。没有自动重试，没有重新生成剧情总结。按先校准再比较候选的原则，校准门槛未通过后，**没有继续运行 production 与去重候选的成对比较**。

逐项评测协议/对照指纹与旧结果一致，A/B Judge prompt 指纹也一致。但 **3.6 分仅来自未失败的 6 个成对对照**，不能与旧结果覆盖全部 12 对的 32.3 分直接推导整体稳定性提升；样本数量也不足以证明模型排名。

逐项校准的 6 次失败均在第二轮：

- `colony-reference`：JSON 解析失败。
- `relationship-reference`、`relationship-omission`、`relationship-contradiction`：`uncertaintyRules` 结果缺失或索引重复。

## Judge 协议修复与第二次复核（2026-09-06）

**结论：格式有效率提高，但整体校准仍未通过；不继续用本轮 Judge 选择生产提示词。** 没有重新生成剧情总结，也没有继续运行保存的 production / L2 去重候选比较。

本轮修改仅作用于本地评测工具：

- rubric 显式提供维度内索引及完整规则 ID；逐项响应改为规则编号作键的对象，本地仍验证完整覆盖与精确引用。
- A/B system 与实际候选字段名严格对齐，规则引用使用显式 ID。
- 增加可选 `STORY_ECHO_EVAL_JUDGE_OUTPUT_MODE=json_schema`，只用于 Judge；默认 `text` 保留兼容接口用法。不支持时明确失败，不重试、不自动降级。
- 增加最多 3 次请求的协议冒烟命令、脱敏失败响应预览和请求/响应哈希；输出模式纳入连接指纹，新旧评分协议不能直接比较。评分权重、通过阈值、来源与 rubric 内容未变。
- 生产 `src/`、`dist/`、manifest、版本及 lockfile 均未改变；长链问答协议也未改动。

依据 [OpenAI Structured Outputs 指南](https://developers.openai.com/api/docs/guides/structured-outputs#supported-schemas)，所有 schema 对象声明完整 required 字段及 `additionalProperties: false`，规则键和 verdict 均受约束。Schema 不能保证评审在语义上正确；本轮结果正好说明这一边界。

### 实测结果

请求模型仍为用户配置的 `gpt-5.6-sol`，使用同一 Judge 连接、`temperature=0` 和非流式请求。先执行 3 次冒烟，全部通过；再执行 24 次逐项评分与 48 次 A/B 对照。两套完整校准进程并行，各进程内部逐次请求，最多 2 个请求同时在途。总计 **75 次请求**，没有自动重试；这不是对并发与串行差异的控制实验。

| 指标 | 本轮结果 |
| --- | ---: |
| 冒烟通过 | 3 / 3 请求 |
| 逐项响应解析及结构/引用检查通过 | 24 / 24 |
| 逐项符合已知对照 | 23 / 24 |
| 错误放行 / 错误拒绝 | 0 / 1 |
| 最小好坏稿分差 | 16.4 |
| 12 个完整两轮对照的最大分差 | 19.3（门槛 10） |
| A/B 响应解析及结构/引用检查通过 | 48 / 48 |
| A/B 两位置一致且符合预期 | 16 / 24 对 |
| A/B 无一致有效结论 | 8 / 24 对 |
| 跨轮判断不同的 A/B 用例 | 6 / 12 |
| 总校准门槛 | 未通过 |

旧协议的逐项解析失败为 6/24，本轮为 0/24；但 A/B 对照一致率由旧轮 23/24 变为本轮 16/24。协议、请求时间及输出形式均有变化，不能据此单独归因到 schema，也不能宣称新协议带来了总体准确率提升。

### 可直接复核的误判

1. `custody-reference` 第二轮从第一轮 100 分降至 80.7，判不合格。候选明确写了顾岚自称所有权但没有登记证明，以及沈青“因此”按未知物证封存。Judge 却称这些认领和因果信息没有明确表达；其所引用的片段本身就包含这些内容。还出现了引用编号虽有效、却不支持该项 reason 的情况。精确引用存在性检查不能证明语义支持。
2. `colony-reference-vs-omission` 两轮均在一个位置误称完整稿缺少氧气/停火倒计时、资源权属和后续下潜任务。另一位置则正确识别。离线 HTTP 请求路径回归确认两种位置均发送所有候选片段，包括“目前余六天”“现余二十小时”“已运到但未安装”；没有本地切片截断这些内容。
3. 第二轮的三组 `*-reference-identity` 中，完全相同的 A/B 文本都出现了被判为一方更好的响应；这是明确的评审异常，不是两份总结的真实差异。
4. `relationship-reference-vs-omission` 第二轮两个位置都声称缺少 `candidate_A_segments` / `candidate_B_segments`，尽管构造函数在两个位置均发送了这些字段。

8 对失败的完整列表：`colony-reference-vs-omission` 第 1、2 轮；第 2 轮的 `custody-reference-vs-omission`、`custody-reference-vs-verbose-error`、`custody-reference-identity`、`relationship-reference-vs-omission`、`relationship-reference-identity`、`colony-reference-identity`。

现有证据定位到**当前 Judge 连接返回的评审不可靠**，不能判定是模型本身、代理链路处理或其他上游因素。本地请求路径测试只证明客户端没有漏传，不证明上游最终收到的内容未变。下一步宜先做小规模、完全串行的同文对照，保留实际请求指纹及供应商请求 ID，再考虑调整评审输入结构，并用留出样本复核；不要用放宽门槛或重复直到通过的方式接受这些结果。

`pairwise-calibrated-inline-v2.json` 完成 **72/72 次有效判断、36/36 次双向比较**，全部预期胜方与双方可用性标签正确，跨轮分歧为 0，网络/格式/引用错误为 0。其中 22 次双向比较选择完整稿，14 次判平局；对应的是每轮 11 对完整/坏稿和 7 对同文/等价稿，而非真实候选胜率。

全部请求严格串行，`maximumInFlight=1` 且时间没有重叠。新布局保留了坏稿识别能力，又能把语义等价改写判平局；本次没有修改生产 prompt，也没有调低阈值。接口自报模型为 `gpt-5.6-sol`，不是实际模型身份的独立认证。

**这一结果使当前 A/B 协议达到可以启动定向 prompt 实验的工程门槛。** 它不证明真实长聊天的全部质量，也不认证另一套逐项数值打分协议；因此暂不继续使用旧的“100 分”结果选 prompt。已新增 `eval:generate`：仅生成并保存正文和来源指纹，不调用 Judge、不输出质量分；再交由这个已校准的 A/B 协议比较。生成空响应/截断/网络失败或无法保存时停止，不重试、不消耗后续用例。

### 真实候选复评：有可修正的证据，不支持自动排名

校准通过后，直接复用 `l2-production-v1.json` 与 `l2-dedup-v1.json` 中已生成的四组正文，来源指纹均通过预检，没有重新生成。生成模型为 `deepseek-v4-flash`，Judge 为当前配置的 `gpt-5.6-sol`，不是同模型自评。比较结果记录所用校准文件内容指纹，保存在 `evals/results/l2-pairwise-calibrated-v1.json`。

16/16 请求 HTTP 200 且 `finish_reason=stop`，无格式/引用错误；但 8 次双向比较只有 3 次同时保持胜负与双方可用性标签一致，另 5 次为不一致。3/4 场景跨轮结果变化；**compare 的 `passed=false` 必须保留，不能把校准集通过解释成实际排名也通过。**

| 场景 | 第一轮双向结果 | 第二轮双向结果 | 结论 |
| --- | --- | --- | --- |
| 关系反转 | 不一致 | 不一致 | 四次胜方都偏向去重候选，但原稿“可安全续写”标签在位置间变化；不足以作为自动放行依据 |
| 十条并行剧情 | 去重候选胜 | 不一致 | 时间锚定有改善线索，但弱优势与平局之间不稳定 |
| 校园群像 | 不一致 | 平局 | 两边均有扩义问题，不能因一边的问题更小而忽略另一边 |
| 修仙资源与誓约 | 原稿胜 | 不一致 | 原稿保留了候选遗漏的动机，但轻微优势与平局之间有变化 |

因此**不推广旧 `l2-state-dedup` 候选**。原先总字数仅下降 3.4% 的事实没有改变；每个 prompt/场景仍只有一次生成，不能将两份输出的所有差异都归因于 prompt，更不能把压短本身作为优化成功。

以下是对来源与候选正文的具体复核，和 Judge 的严重性/胜负标签分开使用：

1. **状态被无依据细化。** 关系来源只写“追查幕后者、落网后答复”，生产稿却写“幕后者身份与动机尚未查明”；继续追查并不能证明身份、动机都未知。Judge 四次都指出这个扩写，但对其是否足以判整稿不可用存在分歧。
2. **范围、频率、关系事实被强化。** 校园来源明确留宿等私下亲密，去重稿增为“同住”；生产稿把吃醋、不舒服推成已明确的“抱有恋爱感情”，标题还加入当前来源未提供的“京都大学”。这些断言在更完整原聊天中可能存在，但本评测输入没有，不能由模型自行补全。
3. **动机在压缩中脱落。** 修仙来源明确谢临“受闻鹤命令保护宁昭”，生产稿保留保护目的，去重稿只剩受命隐瞒。信任修复的状态虽未丢失，理解人物选择所需的目的变弱。
4. **主题重排带来时序风险。** 修仙去重稿把来源第 7 条的坦白提前接在第 3 条破剑/魂灯之后，并用“此时才承认”连接；交易、报名等来源第 4–6 条被放到后面。按主题组织本身不是错误，但新增时间连接词会暗示输入没有确认的紧邻先后。此项来自本轮直接源码/正文复核，不冒充 Judge 的稳定共同结论。

### 第一批 prompt 实验的具体范围

现在可以开始**有证据复核的小步 prompt 改进**，不再需要继续等待一个“所有细微措辞都能稳定排名”的 Judge。当前工具可以辅助找问题；仍不能无人复核、只按总分或胜率发版。

先只试一个 L2 变体：**保持原有覆盖要求，补充证据粒度与强度约束**。建议表达如下（本轮仅记录方案，未写入生产或候选 prompt）：

> 保持来源的事实粒度与确定程度，不把概括状态、暗示或未交代的信息扩写成更具体的既定事实。仍在调查不等于身份或动机均未知，暂时留宿不等于长期同住；动机、关系、次数、持续性、授权范围与行动完成状态，均不得强于来源明确支持的表述。来源只支持行为或感受时，保留该行为或感受，不代替角色确定更深一层的内心结论。

这是一段待验证的通用约束，不是把测试人物或标准答案塞进 prompt。若有效，再分别测试“保留解释选择的动机”和“主题重排不新增时间连接”两个独立变体，不一次堆入多组规则。

第一轮实验验收建议：

- 使用 `eval:generate` 为 production 与单一候选分别做至少两次独立生成；固定生成模型、来源、L2 8,000 Token 上限，不改变世界书规则、L1/L3+ prompt 或产品机制。
- 先检查上述无依据扩写是否减少，再检查重要事件、保护目的、时间顺序、资源与承诺条件是否被删掉；**不以字数下降作为必要通过条件**。
- 当前四个场景属于已见开发集；另补不同人物/题材的独立验证样本。逐条回到来源检查新增断言，不只检查 rubric 已列条目或是否命中关键词。
- 再运行已校准的双向 A/B，并保留分歧；不把“稍好”和“平局”的摇摆强行平均成精确分数。没有稳定证据或出现事实回归则不合入生产。
- 小样本改善后再跑既有长链保留性回归，最后才考虑生产修改、版本更新和推送。本轮没有执行这些后续步骤。

## L2 证据边界独立实验（2026-09-06）

实验前固定范围：新增 `l2-evidence-boundaries` 本地变体，只追加一段通用的事实粒度、确定程度及适用范围约束，保留明确事实，未加入上一轮具体剧情的例子或标准答案。不叠加去重规则，不同时调整动机保留、时序组织或长度策略。参考 [OpenAI 准确性检查建议](https://developers.openai.com/cookbook/examples/chatgpt/chatgpt_prompt_guide/chatgpt_prompt_guide#6-improve-accuracy)，把“避免编造”和“必要信息完整”同时作为检查目标；具体收益以本项目实测为准。

四个既有 L2 开发场景：关系反转、十条并行剧情、校园群像、修仙资源。每个 prompt 各做两轮新生成，共 16 次；顺序为 production r1 → candidate r1 → candidate r2 → production r2，以减轻固定先后顺序的影响。生成模型为已配置的 `deepseek-v4-flash`，输出预算保持每例 8,000 Token，来源和 rubric 不改。串行、无重试；若生成失败或截断，不补抽该样本。

生成完整时，分别比较同轮 production/candidate，沿用 `pairwise-calibrated-inline-v2.json` 校准证明、`inline-segments` 布局及 strict JSON schema；Judge 保持 `gpt-5.6-sol`。每组双向、两次评审，最多 32 次 Judge 请求。两次生成与同一正文的重复评审分别报告，不混淆样本数。

验收：逐条回到来源核对无依据扩义、重要信息遗漏、承诺/资源条件及顺序，不以变短或 Judge 总胜率代替事实检查。没有稳定改善或出现事实回归则不合入生产。本轮开发集不能当作独立留出验证；只有先通过本轮，才进入新题材验证和长链回归，之后才考虑生产推广。

- GPT 使用“玄霄宗”并非同类无依据命名：本修仙用例的世界背景确实提供该宗门与剑冢规则，允许用于理解身份和世界设定。相反，并行用例没有把“北门”明确归属到苍梧城，不能仅凭最后抵达该城就补出地点关联。

其他风险单独保留，不与明确新增事实混算：GPT 部分按主题重排内容后加入“与此同时”“之后”等连接词，可能暗示来源没有确认的同步或紧邻先后；修仙“暂缓进入/深入天井”也比来源的“先回宗门、再调查”更具体。主题合并本身并非错误，尚不能仅据段落顺序宣判所有这些句子都造成时序反转。

### 结论和下一步

**当前证据不支持通过换模型解决事实扩义，也不支持把问题单独归咎于 DeepSeek。** GPT 在关系规则范围与校园局部保留上有改善信号，但同时在地点归属、地图来源和任务阶段上新增内容；两者都保留多数重要剧情，又都能在组织成文时写出来源没有支持的关联。这里比较的仍是当前两个接口配置的小样本，不作模型总排名或长期错误率估计。

生产 prompt 与默认模型保持不变，不把任何历史候选合入生产，不调用 GPT 给自身输出补一个独立评分。下一步更有针对性的实验是“实体归属与条件原样保留”的小型正反例：让模型看到如何合并剧情而不补出居住关系、所有权、信息来源或更强的完成条件。例子需使用新人物/新题材，且另留独立验证样本；不能把这四个开发案例的答案直接塞进 prompt。是否有效仍需与生产 prompt 在固定来源下对照，不承诺仅加示例就能解决。本轮没有新增该候选或修改任何生产代码。

### 确定性风险校验结果（2026-09-08）

已实现仅本地研究用的两类字符串校验：完成阶段升级与明确否定边界丢失。20 个开发例经过可追溯的多轮校准后达到 20/20、precision/recall=1，约 1,888 字来源加 1,368 字摘要的基准 p95 为 4.910ms；随后冻结规则、计分器和 20/10 数据集哈希，只运行一次 10 例 holdout。

Holdout 仅 5/10 整例完全匹配，总体 precision/recall/F1 均为 0.700，包含 3 个 FP 和 3 个 FN。词序变化、同义动作、指代、后续真实完成和无动作词的所有权未知都会使规则误报或漏报。虽然 p95 4.894ms 达标，质量明显不达标，因此不接生产、不阻断保存、不自动重写，也不根据同一 holdout 继续补词刷分。

下一步回到尚未完成的 L2 命题级发言归属：先新建未使用过的开发/holdout 场景，专门标注“谁说了什么、谁知道什么、什么只是旁白事实”，建立 production 基线后再决定是否值得一个最小候选。完整过程、失败类型和冻结哈希见 [阶段总结确定性风险校验实验](PROMPT_EVAL_DETERMINISTIC_GUARDS_EXPERIMENT.md)。

### L1 精简证据契约结果（2026-09-08）

按用户确认的直接优化方向，新增仅本地候选，把 2,090 字符的生产 L1 system prompt 整合成 1,501 字符的证据契约，集中行动阶段、主体/对象/知情绑定、局部顺序、证据优先级、压缩取舍和停止条件。v1 两轮自动通过 8/8、7/8，且人工复核确认稳定修复恋爱与医疗例的关键顺序、归档指示升级；没有 major/critical 新错，但正文较 production 平均增长 13.1%。

后继 v2 只强化来源明确无影响片段的省略，prompt 为 1,577 字符。两轮均 8/8，关键事实改善继续稳定，生成请求输入加输出总 Token 约少 10.6%；然而持久化正文仍平均长 12.1%，低价值过程两轮都有残留，并稳定把“此前体检发现”轻微后移为“本次复查发现”。按请求前门槛未运行四个 holdout，也未修改生产 Prompt。

下一步不继续围绕这八个开发例追加省略句。若继续 L1，应新建长篇自然 RP 密度集：每例接近真实 20–30 轮，不用“这段不改变状态”之类元叙述标注低价值内容；分别度量关键事实/因果保留、输出 Token、重复率及后续问答可恢复性。只有精简契约在该集同时保持语义收益和实际压缩率，才值得作为新实验冻结并进入新的隔离验证。完整指纹、逐轮结果和停止理由见 [L1 精简证据契约实验](PROMPT_EVAL_L1_LEAN_CONTRACT_EXPERIMENT.md)。

### L1 自然长篇验证与 Holdout（2026-09-08）

用户明确将生成长度从硬门槛调整为诊断项后，新增三个未参与候选设计的自然长篇场景，每例 15 个完整往返、30 条消息，不含“这段没有改变状态”等显式省略提示，也不配置自动压缩区间。Production 与冻结 v2 各跑两轮：候选逐来源语义通过 6/6，production 为 4/6；事实保留 98.8 对 92.0，不确定性 100 对 96.5。候选正文长 19.5%，但生成输入加输出总 Token少 3.3%，且没有 major/critical 新错。详情见 [L1 自然长篇 RP 验证](PROMPT_EVAL_L1_NATURAL_VALIDATION.md)。

随后解封此前从未运行的四例 L1 Holdout，production 与 v2 各两轮。两组均 8/8 通过，事实、因果、不确定性和聚焦均持平；候选综合均分 98.8 对 98.0，错误扣分 0 对 0.8。Production 两轮都无依据地把唐岚复查安排在禁潜期满后，候选没有；候选无 hallucination/chronology error。Holdout 候选正文仅长 1.6%，生成输入加输出总 Token少 11.9%。
