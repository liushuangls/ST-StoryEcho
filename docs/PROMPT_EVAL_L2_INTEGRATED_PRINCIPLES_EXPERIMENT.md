# L2 保真原则整合实验

## 冻结方案（真实请求前）

本轮检验一个收敛后的假设：与其在生产 L2 prompt 后继续追加互相重叠的约束，不如将现有保真原则 1–2 整合成同样两行、等长或更短的结果导向规则。候选必须同时维持原有覆盖范围、重要经历的因果链和关系过程，并把“人物实际表态/回应是剧情事件”和“客观旁白不能改成人物发言”放入同一证据规则。

这遵循 [OpenAI 官方模型提示指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.5#prompting-best-practices) 的两项建议：从能保留产品契约的最小 prompt 开始；对总结/改写任务先说明必须保留的内容，并用目标、成功标准与证据边界约束结果。本实验不照搬特定模型模板，也不假定该指南能替代本项目实测。

冻结候选 `l2-integrated-evidence-events`：

> 1. 覆盖各来源的独有重要推进：剧情与关键因果，关系或立场变化，重要表态、回应及对话确立的事实，决定、承诺与条件，身份、能力、关键资源变化，不可逆后果、人物动机，未决目标、危机、伏笔与未知因果；不得因别处更戏剧化而遗漏。
> 2. 已结束的重要情节若体现人物性格、关系、价值观或共同经历，仍保留其“起因—选择或转折—结果”，不可压成静态标签。发言者、听者、回应及表达只按来源；旁白事实不得改成人物发言，也不补未说明的动机或关系定性。

被替换的生产原则合计 215 个 Unicode 码点、631 个 UTF-8 字节；候选合计 214 个码点、628 字节。候选不改共享证据规则、原则 3–6、L1、L3+、来源、世界书、rubric、用户 prompt 或 8,000 Token 输出硬上限，不含案例人物、已知错误答案、正反例、固定篇幅或结构化输出要求。生产源码不导入该候选。

### 请求与对照

- 复用两份已经固定、未截断的生产基线：`contract-only-production-r1.json` 与 `contract-only-production-r2.json`。二者均为 `deepseek-v4-flash`、temperature 0、同一批七个 L2 案例；保留其文件哈希，不覆盖原结果。
- 候选按相同七例串行生成两轮，共 14 次新生成请求；每轮使用新路径 `integrated-evidence-events-candidate-r1.json` / `r2.json`。不自动重试，不调用 Judge，不运行来源修订或定位器。
- 七例为：关系反转、十条并行剧情、校园群像、修仙资源、巡演剧团、极地科考、城邦和谈。它们已被此前实验使用，因此只用于回归和已知故障检查，不再称为未见留出集。
- 生产基线与候选不是同一时段交错采样，这是明确局限。候选若通过本轮门槛，下一阶段仍须先新增真正未见题材，再决定是否值得盲评或生产修改。

### 通过、停止与来源复核门槛

先检查请求身份、prompt/evaluation hash、响应 ID、模型、空响应与截断。任一请求失败或截断即停止，不补抽、不以部分结果宣称通过。

候选只有同时满足以下条件才值得进入新题材验证：

1. 七例中每条来源的独有推进和原 rubric 关键事实均得到覆盖；重要表态、回应、条件、未决状态及必要的起因—转折—结果不能退化。
2. 城邦和谈的“私印不能证明其父生死或位置”保持客观证据边界，不写成温策或其他人物作出的发言；校园须保留悠承认不舒服且仍未告白，不能把备份事故写成正式入社的原因，也不能扩成同居；关系场景不能把局部规则泛化为“不得再独自行动”，不能把未指定的求助范围绑定给特定人物或加重威胁；修仙不能新增危机动机、上缴义务或扩大未知范围。
3. 并行、巡演和极地场景继续保留所有关键状态、归属、完成阶段、撤回/道歉/回应及不确定性；不得新增地点归属、所有权、发言对象、因果或更强的任务状态。
4. 相对两份固定生产基线，至少有一个已知错误在候选两轮中均消失，且没有新的明确来源错误或关键遗漏。仅字数、文风变化或单轮随机改善不计收益。

任何一项明确失败，就在来源复核后终止：不调用 A/B Judge、不跑长链、不修改生产 prompt。即使全部通过，本轮也只把候选标为“值得新题材验证”，不会直接推广。

## 实测结果

**候选未通过来源门槛，不进入新题材验证、A/B Judge、长链或生产。** 两轮都保留了多数剧情，但同时稳定重现了本轮要解决的两类关键错误；第一轮还遗漏了一个目标表态。等长整合本身没有带来可归因的稳定收益。

### 请求身份与完整性

两轮共 14/14 次生成正常完成，全部 HTTP 200、`finish_reason=stop`，无空响应、截断、网络错误或重试；14 个客户端请求 ID 和 14 个响应 ID 均不重复，接口自报模型均为 `deepseek-v4-flash`。两轮逐案例的 prompt hash、evaluation hash 与 wire request hash 各自一致；候选与固定生产基线的 evaluation hash 全部一致、prompt hash 全部不同，说明只改变了候选 system 文本，没有换来源、rubric 或输出预算。

### 决定与后续方向

保留 `l2-integrated-evidence-events` 作为本地失败实验和可复现证据，不改生产。实际新增 **14 次生成、0 次 Judge**；没有调用来源修订、错误定位器或长链，也没有补抽。

连续几轮的共同结果表明，“旁白事实变发言”不是靠抽象的“不得改写”一句就能稳定解决。下一步先把它拆成一个更精确、可证伪的证据绑定规则：只有来源把**该命题本身**明确归给人物时，才写作人物发言；相邻分句或同段出现不能继承说话者。该候选仍应替换现有文字而非追加，并先建立新的开发场景与完全隔离的题材留出场景，避免继续只对这七例调参。当前实验没有提前创建或运行这个后继候选。
