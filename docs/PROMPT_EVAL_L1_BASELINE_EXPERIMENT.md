# L1 生产提示词质量基线与候选门槛

## 冻结方案（真实请求前）

本轮先审计当前生产 L1 阶段总结提示词，不预设需要增加或删除哪条规则。现有四个 L1 用例已参与过历史调参，不再作为发现新问题的主要证据；新增八个开发用例和四个隔离留出用例，均模拟 SillyTavern 角色扮演中的连续消息，而不是让生成模型复述评分规则。

方法遵循 [OpenAI 官方模型提示指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.5#prompting-best-practices)：从保持产品契约的最小提示词开始，以代表性样本、明确成功标准和证据边界进行小步评测。官方指南是实验方法参考，不证明本项目提示词或某个供应商模型已经合格。

### 开发集（允许在设计候选前查看输出）

1. `l1-audit-dev-romance-boundary-and-answer`：暧昧行为、明确告白、未答复与条件见面。
2. `l1-audit-dev-detective-retraction-and-custody`：旧嫌疑撤回、受污染证词、证物归属与限制解除范围。
3. `l1-audit-dev-cultivation-borrowed-manual`：功法借阅、权限、条件申请、突破代价与资源余量。
4. `l1-audit-dev-orbital-aborted-launch`：旧总结修正、临时旁路、取消发射、候选方案与执行中任务。
5. `l1-audit-dev-medical-consent-and-proxy`：患者决定、有限代领授权、条件性处置与诊断不确定性。
6. `l1-audit-dev-court-audience-and-seal`：秘密知情范围、客观旁白、私印证据边界和条件性政治行动。
7. `l1-audit-dev-idol-license-and-understudy`：著作授权、署名、排练替补、正式阵容和错误指责修复。
8. `l1-audit-dev-worldbook-legend-overridden`：现场事实推翻世界书传说、化名桥接、藏品权属与当前危机。

### 留出集（候选冻结前不查看生成正文或逐项失败）

1. `l1-audit-holdout-heist-planted-audio`：篡改录音、一次性权限、有限合作与撤退方案。
2. `l1-audit-holdout-deepsea-sample-rights`：深海样本、冲突测量、数据同步和潜航资格。
3. `l1-audit-holdout-roadtrip-friendship-boundary`：友情边界、借车责任、退款和条件住宿。
4. `l1-audit-holdout-time-loop-memory-scope`：旧总结纠错、记忆/阅读区分、身份不确定和一次性道具耗尽。

### 评测协议

- 生产提示词、来源、previous summary、世界书、3,000 Token 输出上限和 temperature 0 固定。
- 生成模型使用本地环境中已经配置的 DeepSeek Flash 连接；thinking 按 StoryEcho 生产路径关闭。
- Judge 使用独立配置的 GPT-5.6 Sol，输出采用严格 JSON Schema。Judge 只提供有证据片段的逐项语义判断；最终分数、关键项门槛和错误扣分由本地代码计算。
- 每个用例另有三组左右的本地硬断言，只检查专名、编号、时间及明确状态词。硬断言不进入生成或 Judge 请求，不能替代语义复核；它们只阻止“文风流畅但关键锚点消失”的答案通过。
- 压缩率按待总结消息正文 Unicode 码点计算，只作为诊断，不因长度本身奖励或惩罚事实保真。
- 不自动重试。空正文、截断、网络错误、Judge 格式错误或硬断言失败都原样记录。

### 请求预算与顺序

1. 对八个开发用例运行生产提示词两轮：共 16 次生成、16 次 Judge 请求，分别写入新结果文件。
2. 检查两轮请求/评测哈希、模型身份、截断和硬断言，再逐来源人工复核。只有两轮重复出现的同类缺陷才用于设计候选；单轮随机差异只记录。
3. 若没有可复现且值得改提示词的问题，停止，不创造候选。
4. 若存在重复问题，只设计一个最小 L1 候选；候选必须替换或收敛现有重叠文字，不堆叠题材答案、固定模板或刚性字数。
5. 候选先在八个开发例跑两轮。通过人工来源复核后才解封四个留出例；留出阶段同时生成 production 与候选，不能再根据留出结果修改同一候选。

### 生产候选最低门槛

- 两轮均无截断、空响应或请求错误；来源、rubric 与本地硬断言哈希保持不变。
- 重复故障在候选两轮中都消失，且没有新增关键事实遗漏、主体/对象错绑、错误因果、关系升级、完成阶段升级或世界书覆盖原文。
- 开发集不能只提高总分：所有关键 rubric 和硬断言都须通过，人工来源复核无 major/critical 新错误。
- 隔离留出集同样不出现关键回归。Judge 分数只作辅助；来源逐句可证伪的错误优先于自动总分。
- 达到门槛仅表示“值得修改生产提示词”；实际改动仍需单独审查、完整测试和用户确认，不在基线阶段自动写入 `src/`。

## 实测结果

### 高密度试跑作废为压缩证据

最初八个开发例的消息正文只有约 315–395 个码点，内容本身已接近人工摘要。生产输出压缩比约为 0.92–1.16；这不能证明真实 RP 中的 L1 不压缩，只能说明夹具缺少可删的场景内容。两轮试跑文件保留为过程证据：`l1-production-dev-r1.json`、`l1-production-dev-r2.json`。其中第二轮两次生成已成功，但 Judge 请求出现 `fetch failed`；没有重试或覆盖。

在进行候选设计前，为十二个新例补入不改变剧情状态的动作、环境、寒暄与重复确认，使开发例正文达到 546–617 个码点、留出例达到 526–571 个码点。rubric 的事实、因果、禁写结论及生产 Prompt 均未改变；来源变化使 evaluation hash 改变，因此试跑与正式基线不直接比较。

### 正式生产基线

正式开发集两轮共 16 次生成、16 次 Judge 请求，全部完成，无空响应、截断、网络错误或 JSON Schema 错误；生成模型自报 `deepseek-v4-flash`，Judge 请求模型为 `gpt-5.6-sol`。两轮八例的 prompt hash、evaluation hash 逐例一致。

结果文件与 SHA-256：

- `l1-production-realistic-dev-r1.json`：`effe8cb98a243e336da588bb37b93e0ca234aba88b956d3b705385f5bf46c345`
- `l1-production-realistic-dev-r2.json`：`72d48d04ebf2538e7d2cedcb1a7267282acf41f12b9363386d1ac135ed096db2`

两轮都没有 forbidden claim 违规，Judge 的不确定性维度均为 100；侦探、修仙、轨道站、宫廷和世界书场景的核心实体、归属、权限、条件及旧状态修正总体稳定。世界书传说没有覆盖现场事件。

来源人工复核确认一个跨案例的重复问题：**按主题重组时会改变“触发/要求—回应—执行”的顺序，或把待执行指示写成完成结果。**

- 恋爱例 2/2 都先写贺知远删除动态，后写林晚提出公开边界；来源顺序是林晚先提出边界，贺知远答应后才删除。Judge 分别标为 minor / major chronology error。
- 医疗例 2/2 都先写周宁道歉、作废申请，后写医生澄清无急诊手术指征；来源是医生澄清促成误解撤回。两轮因果规则均只得 partial，第二轮另标 major chronology error。
- 偶像例第二轮把唐蔚“让运营归档评论区截图”升级成“运营已归档”，属于请求/指示被写成已完成；第一轮没有该错误，因此只作为同类旁证，不单独算稳定故障。

部分无后果细节也被保留，压缩中位数约 0.66–0.68；但新夹具为了标明哪些插曲不改变状态，使用了若干显式“没有改变”表述，可能反而提高其显著性。因此本轮不据此修改篇幅或删减规则，避免把夹具写法当作真实产品缺陷。后续若专门优化密度，应再用更长且不含元叙述提示的真实风格样本。

两个 production 结果都把林晚写成“暂不接受也不拒绝/暂不给出接受或拒绝答复”，语义正确；旧本地硬断言没有覆盖这两个同义表达，造成 2 次机械误报。该 `any` 词表已在候选请求前补齐。它从未进入生成或 Judge 请求；既有结果文件和其 evaluation hash 保持原样，不回写历史证据。未来结果因此不能仅凭 romance evaluation hash 与这两份旧文件自动等同比较，需以未变的来源/rubric 和人工复核为准。

### 冻结候选：`l1-event-transition`

生产规则当前写作：

> 讨论中的办法、共同决定和已执行行动分别表述为候选路径、既定方案和已执行事件。

候选只替换这一句，不增加案例人物、答案、题材模板、篇幅要求或新章节：

> 提议、请求或指示、决定与已执行行动分别保持为候选、待执行要求、既定方案和已执行事件；重组同一主题仍按“触发或要求—回应—执行”排序，来源未明确完成就不能写成结果。

原句 38 个 Unicode 码点，候选 81 个码点、243 UTF-8 字节，候选文本 SHA-256 为 `0519ec2738ef539097fe22a72ed59ca25de633a5635a4b5b16a93a05429d0684`。生产 `src/summary/prompts.ts` 不变；候选仅存在于本地 `evals/variants.ts`，且只作用于 L1。

候选的专项目标已经冻结：

1. 恋爱例两轮都恢复“提出边界 → 答应 → 删除动态”。
2. 医疗例两轮都恢复“医生澄清 → 周宁纠误/作废 → 顾禾选择监测复诊”。
3. 任何请求或指示在来源未写明完成时不得升级为结果，尤其偶像例的评论区截图归档。
4. 其余七类事实、关系、知情、归属、条件和不确定性不得回归；输出不能因强制逐条时间线而明显扩张。

下一步固定在同八例运行候选两轮，共 16 次生成和 16 次 Judge，不自动重试。若上述三个目标没有在两轮同时满足，或出现新的 major/critical 来源错误，就停止，不解封四个留出例、不修改生产 Prompt。

### 候选实测：未通过，停止于开发集

总分没有决定候选去留；逐来源复核显示冻结的必过目标没有同时满足：

- 恋爱例 **2/2 仍把删除动态写在林晚提出公开边界之前**，没有恢复“提出边界 → 答应 → 删除”的因果顺序。两轮还都把“完成面试后再考虑”扩写为“答复取决于面试结果”，新增了来源没有给出的决定条件。第一轮 Judge 记为 major hallucination 加 minor chronology；第二轮的有效原始 Judge 响应同样记录 major hallucination 和 major chronology，随后因另一条空 evidence 未通过本地协议。
- 医疗例 **2/2 恢复了**“医生澄清 → 周宁纠误并作废申请 → 顾禾选择监测与复诊”的顺序，说明候选存在局部收益。
- 偶像例第一轮没有升级截图归档状态，但第二轮再次把唐蔚“让运营归档评论区截图”写成“运营已归档”。请求/指示不得升级为完成结果的目标没有稳定满足。
- 其余用例没有 forbidden claim 违规，本地硬断言全部通过；仍有少量非目标问题，例如把“博物馆修复师证件”具体化为“市立博物馆修复师证件”。这些不改变核心否决结论。

决定：**淘汰 `l1-event-transition`，不解封四个 holdout，不修改生产 L1 Prompt。** 它修复了医疗顺序，却没有修复两轮稳定复现的恋爱顺序，并引入两轮稳定的新条件扩写；偶像完成阶段升级也在第二轮复现。按预先门槛，不能用 97.8/98.4 的高均分覆盖这些可由来源直接证伪的错误。

下一轮若继续 L1，不应叠加同类泛化句或针对本例答案。更值得单独冻结的是“来源顺序优先、主题归并仅在不改变局部因果时允许”的输入/写作策略，或先验证带消息顺序锚点的输入表示；仍须使用新的开发/留出题材，并把关系答复条件、指示完成阶段作为硬性来源复核项。本轮没有创建或运行这些后续候选。
