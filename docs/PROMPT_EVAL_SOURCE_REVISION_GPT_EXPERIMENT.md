# 来源核验模型对照：GPT 5.6 sol（2026-09-07）

## 结论

**GPT 修好了更多种已知问题，但仍未通过预先冻结的完整修复门槛，不接入生产。** 28 次核验全部成功，20 稿改变、8 稿原样返回。同居断言、星盘遗漏和咖啡回应错配均完整修复；但三份把旁白写成温策明确发言的稿件只修好一份，另两份仍有“指出”。此项反而少于 DeepSeek 的两份，不能宣称 GPT 在所有边界上都更好。

另有未补回的关键人物表态、未删除的行动原因和性别扩写。没有观察到新增的关键事实反转或整条剧情误删，但有一处历史复查时间细节被删去。一次核验不能提供可靠性保证，正文改动多也不等于修复完整。

附加请求耗时 p50/p95 为 **14,987/24,305ms**，DeepSeek 同稿核验为 2,907/3,621ms。遵循同任务比较建议，本轮同时记录质量与等待代价，不以字数减少或模型名称作为发布依据。生产 prompt、调用流程、默认模型及版本均未修改，没有 commit/push。

## 请求前冻结

上一轮 DeepSeek 来源核验修掉了部分错误，但漏查同居残留、星盘遗漏和部分新增发言。本轮经用户同意，使用已配置的 `gpt-5.6-sol` 连接，在相同任务下做核验对照，不改变核验指令。

- 原稿仍是 `contract-only-production-r1.json`、`contract-only-candidate-r1.json`、`contract-only-candidate-r2.json`、`contract-only-production-r2.json`，各七例，共 28 稿。**输入是原稿，不是 DeepSeek 已修过的稿件**，否则会多一次核验并混淆比较。
- 每稿由 GPT 核验一次，顺序与 DeepSeek 轮相同；不补抽、重试、修改原稿/来源/rubric、切模型或调用 Judge/长链。网络、空正文、截断或保存错误立即停止。本轮最多 28 次新增请求。
- 完整复用 `SOURCE_REVISION_SYSTEM_PROMPT` 和构造器。协议指纹必须仍为 `e88c8d0ba27e24395db33d929042890afb17f92f0435e7da90cc164e418ac1de`，每稿的 model-independent `promptHash`、原稿/原请求/来源/rubric/父结果哈希应与 DeepSeek 轮一致。
- 参数仍为纯文本、temperature 0、非流式、单次超时 300,000ms、接口输出预算 8,000 Token，不给核验模型评分规则或手工错误标签。
- 按现有供应商适配，DeepSeek 有 `thinking: disabled`，GPT 不发送这个专用字段，也不新增 `reasoning_effort`。这是用户现有两条连接的同任务对照，不声称隔离了代理差异、推理计算量或模型底层部署；不把供应商自报的模型名当身份认证。

参考 [OpenAI Docs 的同任务模型比较建议](https://developers.openai.com/api/docs/guides/deployment-checklist#choose-a-gpt-56-model)，同时观察任务结果与耗时。本轮不更换默认模型，也不做全模型排名。

## 判定规则

逐份与原稿、原始来源及已保存的 DeepSeek 修订比较，分别列出修复、残留、误删和新增；“正文有变化”不算修复，“模型不同”不等于独立评分。

只有全部主要含错输入都被完整修复、没有新增关键错误或遗漏，才支持进入后续验证；不因平均表现更好就接入生产。七例是多次用于迭代的合成回归集，既不是独立留出集，也不是用户人工金标准。若 GPT 生成修订，不再让同一模型为自己的修订提供所谓独立 Judge 分数。

### 其他改善与残留

- **关系四稿**：保留合作—违约—暂停—有条件恢复的过程及落网后答复表白。GPT 修掉两个 candidate 的“安全→性命”、production-r2 的额外“声张”；candidate-r2 去掉未经证实的幕后者身份/动机未知，也把感情答复条件从“事件了结”改回“幕后者落网”。这些是具体改善，不是因为输出更短。
- **校园四稿**：三份原有的明确恋爱/超出家人内心定性被改为来源中的吃醋和不舒服，candidate-r1 泛化“千纱清楚”及“本地备份”也被去掉；四份伤势判断均由“可完全恢复”收回为“可以恢复”。不过 **candidate-r2 仍只写悠感到不舒服，没有补回向千纱承认不舒服的表态**，该行为属于原 rubric 的关键事实，不用总体关系标签掩盖此缺口。production-r1 对接受咖啡仍是隐含交代，而非明确写出，属于旧有粒度缺口，不是本次新增错配。
- **修仙四稿**：production-r1 的“伤势可能极重”改回“重伤的可能性很高”，candidate-r1 的“极高”也收回为“很高”；production-r1 删除凭空指定找到师尊所在地点的措辞。但 **production-r2 仍有“为应对险境”**，来源只写服丹强行结丹，未给此动机。candidate-r2 原样返回，仍把未愈裂纹写成结丹“代价”；这是更强的因果表述风险，单独记录，不与资源归属反转混算。
- **极地四稿**：candidate-r1 仍以“她”指代来源未明示性别的祝禾，核验只删去一处“因此”，没有修掉性别扩写。production-r1 将伤后“需等两天后复查”改为“需等复查决定”，删除了一处历史时间细节；末段“次日复查”仍在，按周四最新时间仍可定位周五复查，且复查前不能穿越的资格边界没有被改坏。这是局部信息损失，不计为整项复查期限丢失。

## 后续边界

仍不推广此核验流程，不将任何历史候选替换进生产，不补抽一份“通过稿”。两模型都能修掉一部分错，却都漏查，且 GPT 在明确人物发言这一目标上修复更少，说明“换更好的核验模型就够了”尚无证据支持。

下一步建议只做**错误定位实验**：让本地核验器先列出草稿片段、对应来源片段和具体差异，配上无错误对照，测它是否能识别新增发言与遗漏表态、是否误报。当前只有完整修订正文，无法区分“没发现错误”与“发现但没有落实修改”。先验证定位能力，再决定是否值得做有依据的最小修订；不直接再加一次全文核验或跑昂贵长链。

该实验尚未创建或执行，需另行冻结 prompt、样本和请求数；结构化的诊断记录若采用也仅用于本地测试，不改变插件总结的自然语言输出。新题材与长链仍是后续必要验证，当前七例已被反复用于开发，不能再当作未见留出集。
