**额外禁令得到局部改善，发言对象仍未稳定；本轮不替换生产 prompt，不进入 Judge 或长链。** 14 次生成均成功，两次关系稿都不再添加“不得再独自行动”，原有关键因果和承诺仍在。校园说明对象却仍有一次被补成“向悠说明”（上一候选同样是两次中一次），不能算该目标已经改善。修仙稿还把“重伤可能很高”强化为“可能性极高”。这些结果支持保留候选与证据，不支持发版或宣布彻底解决。

## 请求前冻结的方案

用户同意继续上一轮的最小改进。本轮新候选为 `l2-binding-scope`：完整保留生产 L2 prompt 与 `l2-binding-examples` 的两个正反例，唯一变化是追加以下段落：

> 约定、承诺、许可与禁令优先沿用来源的完整关键语句，保留提出者、承担者、条件和适用范围；只保留来源已有的限制，不把提醒、通报义务或局部要求改写成额外禁令。发言对象与知情范围同样是事实：来源未指定听者时，沿用未指定的表述；不因另一角色出现在附近，就补写向其说明或认定其已经知情。

依据 [OpenAI Docs 的准确性建议](https://developers.openai.com/cookbook/examples/chatgpt/chatgpt_prompt_guide/chatgpt_prompt_guide#6-improve-accuracy)，把关键事实回到提供的原文，并同时检查完整性和无依据假设。本轮不要求输出推理过程、清单或不确定性标签，不改变纯文本输出协议、L1/L3+、8,000 Token 硬上限或模型。官方建议不能保证这段文字有效，须以实际输出核对。

冻结顺序与范围：

1. 七个已使用案例各生成两次，共 **14 次**串行请求。使用 `deepseek-v4-flash` 现有连接、temperature 0、非思考、300,000ms 超时；不重试、不补抽第三次、不切换模型。两份结果用新路径，运行前检查不存在。
2. 对照是上一轮 `binding-development-candidate-r1/r2.json` 与 `binding-validation-candidate-r1/r2.json`，辅助参考原 production 结果。逐例来源/rubric 和旧候选指纹核对一致后比较；不重新采样基线。时间不同构成限制，不能将差异全部归因于 prompt。
3. 逐来源核对全部事实、因果、条件、专名与新增断言，重点检查关系案例额外禁令、校园说明对象、城邦旁白变发言、极地准入与姓名，同时检查原有承诺、动机和并行支线是否回退。
4. 若两个目标在重复样本中仍失败，或出现新的关键事实遗漏/反转，停止后续付费 Judge 与长链，不在看到答案后继续改段落重抽。轻微拼写和模糊衔接单列，不冒充关键状态反转，也不抹去。
5. 只有上述筛查有一致改善且无关键回退，才用既有校准与独立 GPT Judge 做完整四个旧场景的双向、两轮比较（先第一份生成，最多 16 次；无跨轮分歧再考虑第二份）。通过后才进入真实生成子总结的 L1→L2 链路。不会因票数或字数就自动替换生产 prompt。

七例由四个旧开发场景（关系、并行、校园、修仙）与上轮新增三例（剧团、极地、城邦）构成。它们都是合成开发/回归样本，不再称未见留出集；不读取真实私人聊天。既有 corpus、rubric、Judge 协议、校准文件均不改，不把具体角色名或标准答案放入新段落。

## 停止原因与下一步

本轮实际为 **14 次生成、0 次 Judge、0 次长链请求**。生成成功不等于质量通过；因为指定的听者目标没有在重复样本中稳定解决，按冻结条件停止后续费用。没有修改 rubric 给候选放宽标准，没有在同一轮追加第三次生成，也没有为了拿到漂亮投票继续调用 Judge。

当前仍不能从已有证据断言 147 字整段都是有效成分：它同时包含约定与听者两类约束，且只有一个模型、七个已使用场景。下一步应把约定范围约束与发言对象策略分开，保留已观察到的约定改善作为待验证基础；针对“谁说给谁”用不同剧情的局部正反例单独验证，避免继续叠抽象禁令。下次候选及调用边界仍需先冻结，不能把本轮一次不发生当作稳定修复。生产更新与 L1→L2 长链继续留在这些边界验收之后。
