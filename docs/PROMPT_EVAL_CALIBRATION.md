# 质量评估校准记录（2026-09-06）

结论：**对照答案的好坏判定已通过，精确分数的稳定性尚未通过。** 当前 `deepseek-v4-flash` 可以识别这组明显遗漏和错误，但同一答案两轮评分最多相差 32.3 分，不能据此判断两个生产 prompt 相差几分就谁更好。仍需固定独立 Judge 并做人工核对。

本轮只调整本地评估工具、夹具、评分协议和文档，没有修改生产生成 prompt、分层合并机制或默认配置。此前修复已作为 v0.21.16（`04f4bc4`）推送；本记录对应其后的 v0.21.17 评估改动，构建产物仅同步版本号。

## Judge 校准

使用环境变量中的 `deepseek-v4-flash` 连接，没有配置独立 Judge。候选答案由开发者按来源与规则编写，不调用生成模型，因此此处不是“模型给自己刚写的答案打分”。这些仍是合成对照，不是真人标注的金标准。

三个场景（物证归属、关系反转、殖民地资源）各有四种答案：完整、关键遗漏、事实反转、更长但夹带错误。每个答案独立评审两次，预期标签不发给 Judge。

| 指标 | 严格逐字引文版 | 编号引文与补充规则版 |
| --- | ---: | ---: |
| 请求数 | 24 | 24 |
| Judge 引文错误 | 4 | 0 |
| 符合预期的对照 | 20/24 | 24/24 |
| 错误放行 / 错误拒绝（可计分结果内） | 0 / 0 | 0 / 0 |
| 好稿减同组最高坏稿的最小分差 | 35.7 | 38.4 |
| 同一答案跨轮最大分差 | 32.3 | 32.3 |
| 总校准门槛 | 未通过 | 未通过（分差应 ≤10） |

编号引文版的三组完整稿均为 100 分，遗漏稿为 42.5–61.6，事实反转稿均为 0，更长但有错的稿为 13.1–52.6。不同缺陷确实能分开，不再是所有答案都接近满分；但同一关系错误稿仍出现 13.1 与 45.4 两种评分，原因在于 Judge 是否对“先写正确状态、后写相反结局”同时扣除不确定性和聚焦维度，判断仍不稳定。

采取的措施：

- 引文改用本地生成的片段 ID，程序还原原文，避免 Judge 调换或改写长引文。
- 明确整篇矛盾检查、等义表达以及只按当前规则扣分，避免正确半句掩盖错误结局，或一处遗漏连带误伤无关维度。
- 密度与语义质量分离。原短夹具并无标定过的压缩区间，报告为未标定，而非要求高密度材料也只剩 15%–30%。
- 基线绑定评分协议、Judge 连接、来源和 rubric。旧量尺不能继续当作生产 prompt 的比较基线。

方法参考 [OpenAI 官方评估指南](https://developers.openai.com/api/docs/guides/evaluation-best-practices#llm-as-a-judge-and-model-graders) 中的明确规则、对照与人工校准建议。当前门槛是项目初始工程选择，不是官方规定或统计置信区间。

## 真实链式生成

两个场景均为新编写的合成酒馆对话，各 32 条消息；每例 4 条 L1 → 2 条 L2 → 1 条 L3，高层读取实际子级生成结果，不是手写的理想总结。测试合并数为 2/2，不覆盖实际默认 10/5 的长轨迹或调度触发。

| 场景 | 原文字符数 | L1 正文合计 | L2 正文合计 | L3 正文 | 原文 / L1 / L2 / L3 探针 |
| --- | ---: | ---: | ---: | ---: | --- |
| 校园：录音许可、信任、退款、知情边界 | 4,623 | 1,808 | 1,915 | 691 | 各 8/8 |
| 奇幻：化名、灵晶账、镜钥、停战、伤势 | 4,462 | 2,078 | 1,798 | 658 | 各 8/8 |

字符数为 Unicode 码点；合计列直接相加各条正文，不额外计拼接分隔符。全部 14 次总结/合并响应以 `stop` 完成，另有 8 次问答请求，共 22 次请求，没有自动重试。未观测到这 16 个问题在压缩后答错。

这不是“总体质量 100 分”：固定选项和有效引文只能检验有限问题，引文存在不等于必然支持整项答案；阅读模型与生成模型相同、素材有重复确认最终状态，均使任务较容易。尚未覆盖数万字、默认 10/5 合并、低重复高密度留出素材或多模型比较。校园 L2 还出现了总体扩写，后续值得人工查看冗余，但长度本身不足以认定质量问题。

- `eval:prompts` 选取 L1 物证和 L2 关系两个原有用例，实际生成和新 Judge 协议均成功；均为 100 分，但正文比分别为 1.190、1.327，密度单独显示为“未标定”。此处只验证端到端工具通路，不用作模型排名。
- `npm run check`：类型检查、构建与离线测试通过。生产 bundle 无变化。
- 真实 LLM 命令未加入 `check` 或 GitHub CI。Key 仅从环境变量读取；结果和原始文本在 Git 忽略目录中。
